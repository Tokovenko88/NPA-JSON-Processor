# ИНСТРУКЦИЯ ДЛЯ ИИ-АГЕНТА: ОБРАБОТКА ИЗМЕНЕНИЙ НПА ЧЕРЕЗ JSON-СЛИЯНИЕ

## 1. ОБЩАЯ СХЕМА РАБОТЫ

Ты выполняешь функцию автоматического применения изменений из одного НПА (изменяющего) в другой НПА (целевой). Вместо сложной программной обработки ты работаешь через детерминированные JSON-промпты и анализ результатов.

**Архитектура проекта:**
```
01_source_target_json/     - Исходный и целевой НПА в JSON
02_json_schema_docs/       - Документация по структуре JSON
03_prompts/                - Промпты для 4 этапов обработки
04_stage_answers/          - Ответы ИИ по каждому этапу
05_result_json/            - Итоговый НПА после применения изменений
06_work_tools/             - Вспомогательные скрипты
AGENT_INSTRUCTION.md       - Этот файл
```

## 2. ВХОДНЫЕ ДАННЫЕ

- `01_source_target_json/source_npa.json` - НПА, который вносит изменения
- `01_source_target_json/target_npa.json` - НПА, в который вносятся изменения
- `02_json_schema_docs/` - документация по структуре JSON

## 3. ПОШАГОВЫЙ АЛГОРИТМ

### ЭТАП 1: АНАЛИЗ УТРАТЫ СИЛЫ (prompt_1_revocation_analysis.md)

**Задача:** Найти в изменяющем НПА указания об утрате силы, относящиеся к целевому НПА.

**Действия агента:**
1. Прочитай `03_prompts/prompt_1_revocation_analysis.md`
2. Подставь в промпт значения из `source_npa.json`:
   - `{date_pub}` = `source_npa.json.date_pub`
   - `{law_number}` = `source_npa.json.npa_number`
   - `{doc_text}` = полный HTML-текст изменяющего НПА (из `source_npa.json`)
3. Выполни промпт через ИИ
4. Сохрани результат в `04_stage_answers/prompt_1_answer.json`
5. Если ответ пуст/null - пропусти этот этап

**Результат этапа:** JSON-массив объектов с полями:
- `structural_element` - где в изменяющем НПА находится указание
- `structural_element_for_delete` - что утрачивает силу в целевом НПА
- `valid_from` - дата утраты силы

### ЭТАП 2: АНАЛИЗ ДАТ И РЕТРОАКТИВНЫХ КЛАУЗУЛ (prompt_2_dates_analysis.md)

**Задача:** Найти специальные даты вступления в силу и ретроактивные clauses.

**Действия агента:**
1. Прочитай `03_prompts/prompt_2_dates_analysis.md`
2. Для каждой статьи изменяющего НПА выполни промпт отдельно
3. Подставь значения из `source_npa.json`:
   - `{date_pub}` = `source_npa.json.date_pub`
   - `{law_number}` = `source_npa.json.npa_number`
   - `{article_number}` = номер текущей статьи
   - `{doc_text}` = HTML-текст текущей статьи
4. Сохрани результат в `04_stage_answers/prompt_2_answer.json`

**Результат этапа:** JSON-массив объектов с полями:
- `applies_to`: "amending_law" | "target_law"
- `action_type`: "special_valid_from" | "retroactive_note"
- `structural_element`: путь к элементу
- `date` / `note_text` / `note_valid_from`

### ЭТАП 3: ИЗВЛЕЧЕНИЕ ИЗМЕНЕНИЙ (prompt_3_changes_extraction.md)

**Задача:** Извлечь все изменения из каждой статьи изменяющего НПА.

**Действия агента:**
1. Прочитай `03_prompts/prompt_3_changes_extraction.md`
2. Для каждой статьи изменяющего НПА выполни промпт отдельно
3. Подставь HTML-текст статьи в промпт
4. Сохрани результат в `04_stage_answers/prompt_3_answer_article_N.json`

**Результат этапа:** JSON-массив объектов изменений с полями:
- `revision_number` - иерархия подпунктов изменяющего НПА
- `structural_element` - целевой элемент в целевом НПА
- `type` - тип изменения: "add" | "delete" | "change" | "new_redaction"
- `description` - описание/HTML изменения
- `new` - только для add: название нового элемента

### ЭТАП 4: ПРИМЕНЕНИЕ ИЗМЕНЕНИЙ К HTML (prompt_4_text_processing.md)

**Задача:** Для каждого изменения типа "change" применить текст модификации к HTML элемента.

**Действия агента:**
1. Прочитай `03_prompts/prompt_4_text_processing.md`
2. Для каждого изменения типа "change":
   - Найди целевой элемент в `target_npa.json` по `structural_element`
   - Получи его текущий HTML
   - Подставь в промпт:
     - `{element_html}` = текущий HTML элемента
     - `{description}` = описание изменения
   - Выполни промпт
   - Сохрани результат в `04_stage_answers/prompt_4_answer_element_ID.json`
3. Обнови HTML элемента в `target_npa.json`

**Результат этапа:** Обновлённый HTML для элементов с изменениями типа "change".

### ЭТАП 5: ПРИМЕНЕНИЕ ИЗМЕНЕНИЙ К JSON (агент выполняет сам)

**Задача:** Применить все изменения к целевому НПА, модифицируя JSON структуру.

**Типы изменений и их применение:**

#### 5.1. УТРАТА СИЛЫ (delete)
Для каждого изменения из этапа 1:
1. Найди элемент в `target_npa.json` по `structural_element_for_delete`
2. Если `structural_element_for_delete == "law"`:
   - Установи `valid_to` активной ревизии заголовка = (дата - 1 день)
   - Создай новую ревизию заголовка с `mod_type = "delete"`
3. Если это структурный элемент:
   - Найди элемент по пути `structural_element_for_delete`
   - Установи `valid_to` активной ревизии = (дата - 1 день)
   - Создай новую ревизию с `mod_type = "delete"`, `body = []`

#### 5.2. СПЕЦИАЛЬНЫЕ ДАТЫ (special_valid_from)
Для каждого изменения из этапа 2 с `action_type = "special_valid_from"`:
1. Если `applies_to == "amending_law"`:
   - Найди элемент в изменяющем НПА по `structural_element`
   - Установи `valid_to` активной ревизии = (дата - 1 день)
   - Создай новую ревизию с `mod_type = "new_redaction"` и `valid_from = date`
2. Если `applies_to == "target_law"`:
   - Найди элемент в целевом НПА по `structural_element`
   - Установи `valid_to` активной ревизии = (дата - 1 день)
   - Создай новую ревизию с `mod_type = "new_redaction"` и `valid_from = date`

#### 5.3. РЕТРОАКТИВНЫЕ КЛАУЗУЛЫ (retroactive_note)
Для каждого изменения из этапа 2 с `action_type = "retroactive_note"`:
1. Найди элемент в целевом НПА по `structural_element`
2. Добавь в `item_notes` элемент:
   ```json
   {
     "text": "Действие положений [structural_element] распространяется на правоотношения, возникшие с [date]",
     "valid_from": "[date]",
     "valid_to": ""
   }
   ```

#### 5.4. НОВАЯ РЕДАКЦИЯ (new_redaction)
Для каждого изменения из этапа 3 с `type = "new_redaction"`:
1. Найди элемент в целевом НПА по `structural_element`
2. Установи `valid_to` активной ревизии = (дата изменения - 1 день)
3. Создай новую ревизию:
   - `valid_from` = дата изменения
   - `mod_type` = "new_redaction"
   - `modified_by_id` = ID изменяющего НПА
   - `body` = массив блоков с новым HTML (из этапа 4, если был change, или из description если new_redaction)
   - `highlights` = результат этапа 4 (если был)

#### 5.5. ДОБАВЛЕНИЕ (add)
Для каждого изменения из этапа 3 с `type = "add"`:
1. Найди родительский элемент по `structural_element`
2. Создай новый элемент:
   - `item_id` = сгенерируй по правилам: `{npa_id}_{type}_{number}`
   - `item_type` = тип из поля `new`
   - `item_number` = номер из поля `new`
   - `item_level` = уровень родителя + 1
3. Добавь в `item_children` родителя
4. Добавь `child_ref` в `body` родителя
5. Создай ревизию для нового элемента с `mod_type = "add"`
6. Обнови ревизию родителя с `mod_type = "change"`

#### 5.6. УДАЛЕНИЕ (delete)
Для каждого изменения из этапа 3 с `type = "delete"`:
1. Найди элемент в целевом НПА по `structural_element`
2. Установи `valid_to` активной ревизии = (дата изменения - 1 день)
3. Создай новую ревизию:
   - `valid_from` = дата изменения
   - `mod_type` = "delete"
   - `modified_by_id` = ID изменяющего НПА
   - `body` = пустой массив или содержимое старой ревизии
4. Обнови ревизию родителя с `mod_type = "change"`

#### 5.7. ЧАСТИЧНОЕ ИЗМЕНЕНИЕ (change)
Для каждого изменения из этапа 3 с `type = "change"`:
1. Найди элемент в целевом НПА по `structural_element`
2. Получи HTML текущей активной ревизии
3. Примени изменения из этапа 4 (prompt_4)
4. Создай новую ревизию:
   - `valid_from` = дата изменения
   - `mod_type` = "change"
   - `modified_by_id` = ID изменяющего НПА
   - `body` = массив блоков с изменённым HTML
   - `highlights` = подсветка изменений из этапа 4

## 4. ПРАВИЛА ГЕНЕРАЦИИ item_id

**Формат:** `{npa_id}_{item_type}_{item_number}`

**Примеры:**
- `123_article_1`
- `123_part_2`
- `123_point_3`
- `123_appendix_1`
- `123_appendix_1_double_1` (для дубля)

**Для элементов внутри structured_table:**
- `123_table_1_section_I`
- `123_table_1_point_1`

## 5. ПРАВИЛА РАБОТЫ С РЕВИЗИЯМИ

### Создание новой ревизии:
1. Найди активную ревизию (`valid_to` = null)
2. Установи `valid_to` = (новая_дата - 1 день)
3. Создай новую ревизию с `valid_from` = новая_дата
4. Скопируй `body` из старой ревизии (если не `delete`)
5. Установи `modified_by_id` = ID изменяющего НПА

### Дата вступления в силу:
- Обычно = `valid_from` изменяющего НПА
- Может быть переопределена специальной датой из этапа 2
- Формат: `DD.MM.YYYY`

## 6. ВЕРИФИКАЦИЯ И ИСПРАВЛЕНИЕ ОШИБОК

После применения всех изменений выполни проверку:

### 6.1. ПРОВЕРКА СТРУКТУРЫ
- [ ] Все `item_id` уникальны
- [ ] Все `item_type` допустимы
- [ ] Все `item_level` корректны (начинаются с 1, увеличиваются на 1)
- [ ] Все `revisions` имеют `valid_from` и `valid_to`
- [ ] Только одна активная ревизия (`valid_to` = null) на элемент

### 6.2. ПРОВЕРКА ССЫЛОК
- [ ] Все `child_ref` в `body` соответствуют существующим `item_id`
- [ ] Все `modified_by_id` соответствуют существующим НПА
- [ ] Нет битых ссылок

### 6.3. ПРОВЕРКА ДАТ
- [ ] Все даты в формате `DD.MM.YYYY`
- [ ] `valid_to` = `valid_from` - 1 день (кроме утраты силы всего закона)
- [ ] Даты следуют хронологически

### 6.4. ПРОВЕРКА ИЗМЕНЕНИЙ
- [ ] Все изменения из этапа 3 применены
- [ ] Нет пропущенных изменений
- [ ] Типы изменений корректны

### 6.5. АВТОИСПРАВЛЕНИЕ
Если найдены ошибки:
1. Дублирующиеся `item_id` → добавь суффикс `_double_N`
2. Отсутствующие `child_ref` → добавь в `body` родителя
3. Неправильные даты → исправь по правилам
4. Пропущенные изменения → примени вручную

## 8. ОБРАБОТКА ОШИБОК

### Если промпт возвращает null:
- Этап 1: нет указаний об утрате силы - ок
- Этап 2: нет специальных дат - ок
- Этап 3: нет изменений - ок
- Этап 4: не выполняется

### Если промпт возвращает некорректный JSON:
1. Попробуй исправить JSON
2. Если не получается - пропусти это изменение
3. Зафиксируй ошибку в логе

### Если элемент не найден:
1. Проверь `structural_element` на правильность
2. Попробуй найти элемент по частичному пути
3. Если не найден - пропусти изменение
4. Зафиксируй в отчёте

## 10. ВАЖНЫЕ ПРАВИЛА

1. **Детерминированность:** Все вычисления должны быть повторяемыми
2. **Валидация:** После каждого этапа проверяй корректность результата
3. **Идempotentность:** При повторном запуске результат должен быть тем же
4. **Безопасность:** Не удаляй исходные файлы, работай с копиями
5. **Логирование:** Фиксируй все действия и ошибки
