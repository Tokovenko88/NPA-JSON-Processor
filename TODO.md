# TODO: Исправление дублирующихся ревизий для «части 1» (16012_article_3_part_1)

## Проблема
Одно изменение («добавить пункт 3 в часть 1») создаёт две ревизии у элемента `16012_article_3_part_1`:
1. Фантомную `add`-ревизию с `valid_to: 22.10.2018` (только `child_ref point_3`)
2. Реальную `change`-ревизию (полное содержимое части)

Это нарушает принцип «одно изменение = одна ревизия».

## Корневая причина
`часть 1` ещё не существовала в целевом НПА, когда применялось изменение «добавить пункт 3».
Механизм отложенного add (`_ensure_path` в `ui_utils.py`) создал плейсхолдер `part_1` с
фантомной `add`-ревизией. Затем при перестройке `article_3` через `sync_structural_element_recursive`
плейсхолдер был слит с реальным парсованным `part_1`, но фантомная ревизия не была удалена —
вместо этого она была закрыта (`valid_to`) и добавлена новая ревизия.
